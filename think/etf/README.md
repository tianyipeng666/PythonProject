# 指数估值与每周定投工具

这个目录用于分析以下指数及其代表性 ETF：

| 指数 | 指数代码 | 默认ETF | 示例目标权重 | 历史估值口径 |
|---|---|---|---:|---|
| 上证指数 | 000001 | 510210 | 5% | 上交所市场PE代理 |
| 沪深300 | 000300 | 510300 | 40% | 指数级PE/PB |
| 上证红利 | 000015 | 510880 | 20% | 指数级PE/PB |
| 创业板指 | 399006 | 159915 | 20% | 创业板市场PE代理 |
| 科创100 | 000698 | 588030 | 15% | 科创板市场PE代理＋中证指数当前快照 |

默认权重只是便于演示预算分配。上证指数、沪深300、上证红利存在较多成分股重叠，不能把三者简单理解成完全独立的资产。请在 `config.py` 中按自己的期限、承受能力和已有持仓调整 ETF 与权重。

## MySQL配置

程序默认要求MySQL，并在每次运行时执行以下流程：联网拉取最新数据 → 自动建表/更新MySQL → 从MySQL读取完整历史 → 计算估值 → 生成Excel报告 → 保存本次分析结果。

设置连接环境变量，不要把数据库密码写进代码：

macOS/Linux：

```bash
export ETF_DATABASE_URL='mysql://etf_user:你的密码@127.0.0.1:3306/etf_data'
```

Windows PowerShell：

```powershell
$env:ETF_DATABASE_URL='mysql://etf_user:你的密码@127.0.0.1:3306/etf_data'
```

检查连接并自动建库建表：

```bash
python -m think.etf --db-check
```

MySQL用户需要拥有`etf_data`数据库的建库/建表和读写权限。如果数据库已由管理员提前创建，只需授予该库读写权限。密码中包含`@`、`:`、`/`等字符时，需要进行URL编码。

## 使用

分析全部五个指数：

```bash
python -m think.etf
```

默认行为是：终端只输出“是否定投、投资倍率、建议金额和主要原因”，同时在下面目录生成格式化Excel报告：

```text
think/etf/output/ETF估值定投报告_日期时间.xlsx
```

如果还想在终端显示完整明细表：

```bash
python -m think.etf --verbose
```

按每周 2000 元基础预算生成参考金额：

```bash
python -m think.etf --weekly-budget 2000
```

只分析沪深300和上证红利：

```bash
python -m think.etf --index 000300 --index 000015 --weekly-budget 2000
```

输出 JSON：

```bash
python -m think.etf --weekly-budget 2000 --json
```

不生成Excel：

```bash
python -m think.etf --no-excel
```

不联网，只使用MySQL中已经保存的数据：

```bash
python -m think.etf --offline
```

仅在排查数据库问题时临时绕过MySQL：

```bash
python -m think.etf --no-database
```

该模式不会保存历史，不能满足长期估值分位需求，不建议作为日常运行方式。

也可以手工指定10年期国债收益率，例如1.70%：

```bash
python -m think.etf --risk-free-rate 1.70
```

## 估值规则

程序使用最近10年（历史不足10年则使用全部可得数据）的PE/PB分位，并加入盈利收益率相对10年期国债收益率的安全垫：

| 综合分位 | 状态 | 常规定投倍数 |
|---:|---|---:|
| ≤20% | 明显低估 | 1.40 |
| 20%～35% | 偏低 | 1.20 |
| 35%～65% | 合理 | 1.00 |
| 65%～80% | 偏高 | 0.75 |
| >80% | 明显高估 | 0.50 |

第一步，有指数级PB时，相对估值采用70% PE分位＋30% PB分位；否则只使用PE分位。第二步，最终综合评分使用65%相对估值＋35%股债收益差评分。这样可以避免“某指数过去长期PE极低，当前PE仍不高却被机械判为极度高估”。程序同时输出：

- 当前PE/PB及历史分位；
- 20%、50%、80%历史参考值；
- 盈利收益率 `100 / PE`；
- 盈利收益率与10年期国债收益率之差；
- 中证指数官网可取得的PE、股息率快照；
- 近5日涨跌和距60日高点回撤。

分位是相对估值，不代表未来一定均值回归。成长指数的PE容易受盈利周期和亏损成分股影响，因此创业板指、科创100还应结合盈利增长、ROE、研发投入和指数成分变化判断。

### 10%、6.4%和6.8%的含义

- 10%指盈利收益率，对应PE=10倍，不是股息率；
- 先前规则中的6.4%也指盈利收益率，对应PE约15.63倍；
- 如果6.8%来自“约3.4%无风险利率的两倍”，它仍是盈利收益率门槛，对应PE约14.71倍；
- 这些固定门槛来自旧利率环境，本程序改用`盈利收益率－实时10年期国债收益率`，不机械使用6.4%或6.8%。

## 大跌加仓规则

程序不会把单日大跌直接等同于低估。只有估值处于“合理”或更低时，才根据下列条件增加本周投入：

| 条件（取最高一档，不重复叠加） | 加仓倍数 |
|---|---:|
| 距60日高点回撤5% | +0.10 |
| 回撤8%或近5日跌5% | +0.25 |
| 回撤12%或近5日跌8% | +0.40 |
| 回撤18%或近5日跌12% | +0.60 |

额外限制：

- 估值偏高或明显高估：大跌不自动加仓；
- 估值合理：大跌奖励最多+0.25倍；
- 单指数建议额最高为基础额的2倍；
- 默认组合单周总建议金额不超过基础周预算的1.5倍；
- 超出常规预算的部分应来自预先准备的“回撤储备金”，不应借贷或使用杠杆。

比较稳妥的执行方式是每周固定一天运行一次。不要盘中看到大跌就连续追加；同一周只执行一次建议，下一周再重新计算。

不需要每天运行。只有出现下列任一情况时，才建议在当周临时重跑一次：单日下跌至少7%、近5日累计下跌至少5%，或者你观察到指数已经明显跌破近期区间。临时运行后也只有程序显示估值“合理/偏低/明显低估”并提高倍率，才执行一次额外加仓；否则等到下周常规定投日。

## 数据库存储

程序自动维护以下MySQL表：

- `etf_index_meta`：指数和ETF映射；
- `etf_index_valuation`：PE、PB、股息率及数据来源/精度；
- `etf_index_price`：指数日线行情；
- `etf_bond_yield`：10年期国债收益率；
- `etf_analysis_run`：每次运行记录；
- `etf_analysis_result`：每个指数的估值状态和定投倍率。

运行过程中不再向代码目录写入CSV缓存或精确数据文件，代码目录中的运行产物只有`think/etf/output`下的Excel定投报告。

## 精确历史估值导入

官方免费接口可以拉取当前或近期的精确快照，程序会每次写入MySQL并逐日积累。但公开接口不能一次性返回完整的5～10年官方PE/PB历史。

如从中证指数、国证指数、Wind、Choice、iFinD、理杏仁等来源获得指数级历史CSV，可以放在代码目录之外，并直接导入MySQL：

```bash
python -m think.etf \
  --import-index 399006 \
  --import-valuation-csv /外部目录/399006.csv \
  --import-source wind
```

Windows示例：

```powershell
python -m think.etf `
  --import-index 399006 `
  --import-valuation-csv D:\market-data\399006.csv `
  --import-source wind
```

字段为：

```csv
date,pe,pb,dividend_yield
```

至少20条有效PE，建议日频或周频覆盖5～10年，且必须使用统一口径。导入后程序会优先使用MySQL中的精确来源。

## 数据口径与限制

- 沪深300、上证红利使用较长的指数级PE/PB历史。
- 上证指数使用上交所市场平均PE作为近似。
- 创业板指使用整个创业板市场平均PE作为代理。
- 科创100使用整个科创板市场PE历史作为代理，并展示中证指数可得的指数级当前PE/股息率快照。
- 中证/国证当前精确快照会逐次积累到MySQL；达到足够历史长度后可自动替代代理历史。
- 免费数据源可能延迟、改变字段或临时不可用；失败时程序使用MySQL中最近一次成功数据并在报告中显示警告。
- 当前版本只生成研究报告，不连接券商、不自动下单。
- ETF价格还可能受到短期溢价/折价影响，下单前应另行检查ETF实时溢价率、成交额和买卖价差。

这是一套纪律化参考规则，不保证收益，也不能替代个人资产配置和风险承受能力评估。
